# Ведомость отделки / зоны HimeraZone_АСП (Archicad 27)

Пользователь — архитектор (АР/АС, жилые дома, секции 1–5). Общение по-русски, коротко, без программистского жаргона.
Эталон оформления — ведомость отделки тома АР (лист 63: «N секция. Ведомость отделки помещений жилого дома»).

## Репозиторий и сборка

- GitHub `lelkametel-gif/archicad-otdelka` (public). Клонировать: `git clone --depth 1 https://github.com/lelkametel-gif/archicad-otdelka`.
- CI: GitHub Actions `.github/workflows/main.yml` на каждый push собирает `VedomostOtdelki.apx` (артефакт **VedomostOtdelki-AC27-Windows**).
  После push ждать: `gh run list -R lelkametel-gif/archicad-otdelka -L 1`, затем `gh run view <id> --log-failed | grep -E "error C|error:"`.
- Тесты логики на Linux (обязательно перед push):
  `g++ -O2 -std=c++17 -Wall -ISrc -o /tmp/t tests/test_otd.cpp Src/FinishCore.cpp Src/FinishReport.cpp Src/XlsxWriter.cpp Src/FinishTable.cpp && /tmp/t out.xlsx a.svg b.svg`
  (b.svg — ведомость + таблица проверки; рендер в PNG через playwright, viewport ~3000 px, fullPage:false).
  Паспорта и ТЭП: `g++ -O2 -std=c++17 -Wall -ISrc -o /tmp/tt tests/test_tep.cpp Src/TepCore.cpp Src/FinishCore.cpp Src/XlsxWriter.cpp Src/FinishTable.cpp && /tmp/tt tep.svg tep.xlsx`.
  Параметры зон: `g++ -O2 -std=c++17 -ISrc -o /tmp/z tests/test_zp.cpp Src/ZoneParamsFile.cpp && /tmp/z`.
- Скачать артефакт CI (`gh run download`) из сессии нельзя — хранилище blob закрыто прокси; пользователь берёт .apx со страницы Actions.
- Заголовки API (чтобы проверить имена функций AC27): devkit
  `https://github.com/GRAPHISOFT/archicad-api-devkit/releases/download/27.6003/API.Development.Kit.WIN.27.6003.zip` → `Support/Inc`.
  Примеры: `ACAPI_Grouping_GetConnectedElements`, `ACAPI_View_ZoomToSelected`, `ACAPI_Element_SetUserData`, `APIWtyp_Poly`.
- Файлы с BOM (utf-8-sig); `RINT/AddOn.grc` — CRLF и BOM: править python-скриптом с сохранением кодировки/концов строк.
- Коммиты: в конце строки Co-Authored-By / Claude-Session из системного напоминания.

## Структура

- `Src/FinishCore.*` — правила (текст `Документы\Ведомость отделки - правила.txt`), классификация стен, подкатегории, строки, геометрия граней (без API, тестируется).
- `Src/FinishTable.*` — раскладка таблиц (линии + однострочные тексты) для рабочего листа: ведомость и таблица проверки; `Render` общий.
- `Src/FinishReport.*`, `Src/XlsxWriter.*` — Excel: листы «Ведомость» и «Расчёт» (каждая стена каждой зоны).
- `Src/TepCore.*` — квартиры, паспорта, ТЭП, файл данных «ТЭП - <проект>.txt» (без API, тестируется). `RenderGrid`/`GridCell` в FinishTable — общая отрисовка таблиц (есть выравнивание влево `left`/`indent`).
- `Src/ZoneParamsFile.*` — файл сохранения/восстановления параметров зон (строки Z/S/N/A, поиск зоны по GUID, иначе по этажу+номеру+имени; пропуск A, B, ROOM_*, GLOB_*, asAddOn_CalcArea/FloorArea/FillArea).
- `Src/Otdelka.cpp` — окно, чтение модели, рабочий лист, команды меню (DoPassports, DoTep, DoTepData, DoSaveZoneParams/DoRestoreZoneParams в конце файла). `Src/AddOnMain.cpp` — меню (8 пунктов).
- Копия этого навыка лежит в репозитории: `.claude/skills/archicad-otdelka-dev/SKILL.md`; таблица категорий — `docs/Категории зон.md`.
- `gdl/` — объект зоны `HimeraZone_АСП.xml`, `Собрать HimeraZone_АСП.bat` (LP_XMLConverter xml2libpart), категории зон XML.

## Меню и окно

1. «Ведомость отделки…» — окно: секция, этажи, толщина пола по категории (только если полы не замоделированы), слой «Полы», потолок, вычитать проёмы, Excel, объект зоны (часть имени, по умолчанию HimeraZone), пропуск скрытых слоёв. Кнопки «Рассчитать», «Рассчитать + проверка зон», «Правила…».
2. «Ведомость + таблица проверки зон» — без окна, последние настройки.
3. «Показать на плане зоны выделенных строк проверки» — тексты таблицы проверки несут userData `OTDZONE:<guid>`; выделенные строки → план этажа, выделение, ZoomToSelected.
4. «Паспорта квартир на планах этажей», 5. «ТЭП по дому», 6. «Данные ТЭП и паспортов (файл)…», 7. «Сохранить параметры зон в файл», 8. «Восстановить параметры зон из файла» (`Документы\Параметры зон.txt`, прежний — «(предыдущие)»).
- Меню и имя надстройки — «ПСО и отделка» (RINT/AddOn.grc).
- Пункты меню с флагами `^E3^ES^EE^EI^ED^EW^EL` (иначе неактивны на рабочем листе).
- Таблица рисуется на рабочем листе «Ведомость отделки - секция N» (перерисовывается целиком); линии в слое текстов.
- Обновление без перезапуска Archicad: надстройка не держится в памяти — .apx можно подменить между запусками; новые пункты меню/элементы окна — только после перезапуска (предупреждать).

## Отбор зон

- Объект зоны: имя содержит «HimeraZone» (HimeraZone22, HimeraZone_АСП).
- Этаж в окне = число из названия этажа («Этаж 1» → 1), иначе индекс. Секция — свойство «Секция №», иначе параметр зоны `asAddOn_stStaircaseCode`.
- Пропуск зон на скрытых слоях (галочка). Отчёт: по этажам, слоям, категориям, другие секции, другие объекты, hotlink.

## Подкатегории и строки (как в томе АР)

- Подкатегория по первой цифре кода категории (если код пуст — первое число в имени категории). Порядок:
  3 Тех.помещения (подвал), 5 Встроенные помещения, 1 Квартиры, 6 Типовой этаж, 4 1 этаж, 2 Общедомовые помещения, 7 Чердак; 8, 9 — не входят («-»).
- Квартиры — строки по видам помещений ([Строки по категориям]): 101 | 102 | 103,104,108 | 105 | 106,107. Остальные подкатегории — строка = одинаковая отделка потолка и стен.
- Наименование строки = перечень имён зон без повторов («\n» в имени → пробел; следующие со строчной, аббревиатуры как есть). Одинаковый перечень с разной отделкой → «(2-14 эт.)».
- Соседние строки подкатегории (одного набора категорий) с одинаковой отделкой стен — стены одной объединённой ячейкой.
- Правила версионируются (`kRulesVersion`, строка «# Версия правил: N»): старый файл заменяется, прежний сохраняется «(старые)». При изменении правил по умолчанию — повышать версию и предупреждать пользователя.

## Столбцы стен

- Столбцы: 1 Монолит. ж/б стены; ж/б пилоны; 2 Керамзитобет. перегородки, КБ, вентблоки, кирп. шахты; 3 Межкомнатные перегородки ГКЛ.
- Код слоя из названия многослойной конструкции «| Ст_В| Ш 15_КБ 190_Ш 15» (части по «|», слои по «_», буквы в начале). Есть ЖБ / Ж/Б / Железобетон / Бетон — всегда монолит (ЖБ первым в правилах). Однослойная — по имени строительного материала («Ж/Б | монолит-V», «Керамзитобетон»). «Штук | Гипс» — монолит. Колонны — столбец 1. На плане: закрашенные стены — монолит, белые — КБ.
- Столбец 3 только в «Квартирах», кроме санузлов, ванных, душевых, туалетов, балконов, лоджий, террас — иначе столбец 2 ([Столбец 3]).

## Расчёт стен (главное)

- Основное — связи зоны (`ACAPI_Element_GetRelations`, wallPart tBeg/tEnd, окна/двери этих участков).
- По плану добавляются только элементы **этажа зоны**, которые ограничивают зону, но не связаны с ней (стена другого этажа не берётся), — с заметкой «не связаны с зоной, взяты по плану» в таблице проверки и «(по контуру)» в «Расчёте». Колонны зоны — по открытым граням.
- Геометрия (`ExposedFaces`): контуры элементов (прямоугольник ортогональной стены/колонны, многоугольная стена — полигон из memo); от грани наружу до ~5 см: зона без элементов — отделывается; элемент раньше — закрыто (облицовка); элемент сразу за зоной — щель до 5 см не отделывается (пилон у стены).
- Приоритет на общей грани, как пересечение в Archicad: колонна (2) > ж/б стена (1) > кладка/ГКЛ/штукатурка (0). Элемент ниже приоритетом, проходящий сквозь наш (пилон 200 в стене КБ 205), нашу грань не закрывает. Стена из связей, частично закрытая колоннами/ж/б, уменьшается пропорционально («минус … м под колоннами / ж/б»).
- Высота отделки — строго высота зоны − потолок; пол вычитается, только если полы не замоделированы (нет перекрытия в слое «Полы»): «Толщина пола» зоны, иначе по категории из окна. Элемент ниже зоны — та же высота + примечание «ниже зоны, проверить высоту».
- Зоны 8NNN/9NNN по плану не считаются.

## Таблица проверки (справа от ведомости)

Этаж | № | Имя | Категория | Код | Потолок | Длина стен: монолит, КБ, ГКЛ | Высота отделки («2,97 (до 2,90)») | Проёмы | Площадь: монолит, КБ, ГКЛ | Подкатегория | Отделка потолок / стены | Примечание (по плану, ниже зоны, без столбца). Итоги по подкатегориям = суммы подраздела ведомости.

## Excel «Расчёт» — как разбирать расхождения

Пользователь присылает `Документы\Ведомость отделки - секция N - эт. X.xlsx` (проверять имя: эт. -1 vs эт. 1!). Колонки: этаж, № зоны, категория (имя), группа, имя зоны, отделка, площадь потолка, толщина пола + источник, ID, конструкция, столбец, длина, высота элемента, высота отделки, проёмы шт/м², площадь. Строки «не взят по плану: … — причина» (скрытый слой / другой этаж / закрыт скрытым / грань отдана соседнему), строка «Сверка: периметр зоны / стены и колонны / проходы». Разбирать: `python3 -I` + openpyxl, фильтр по категории зоны; сверять с эскизом пользователя по длинам (её M = монолит, КБ), высота её = высота зоны.

## Паспорта квартир и ТЭП (сделано 05–06.11.2026)

- Квартира = зоны категорий «Помещения квартир» (1xxx) с одинаковым параметром «Квартира» (asAddOn_stApartmentCode) на одном этаже одной секции (выбор пользователя; не по дверям).
- Площадь помещения: asAddOn_CalcArea (как в штампе), иначе calcArea Archicad; округление до 0,1 и сумма. Летние: балконы/террасы 1060,1061 ×0,3, лоджии 1070 ×0,5. Жилая — 1010,1011. Тип: число жилых комнат «NК»; студия «С» = 1 комната без кухни 1020/кухни-столовой 1022.
- Объект `gdl/Паспорт_АСП.xml` (MainGUID 6443E33A-D269-427D-BAE2-7A69743D05AB, сборка `Собрать Паспорт_АСП.bat`): stType, stLiving/stArea/stTotal/stReduced (строки), r* числа, stKey «секция|квартира». Надстройка ищет его по имени, новые ставит снаружи у ближайшего края этажа секции, стоящие (тот же этаж + ключ) обновляет, без ключа не трогает, исчезнувшие удаляет.
- Паспорта: ставятся у самой большой жилой комнаты квартиры, снаружи плана, в свободном месте (FreeSpace: зоны, стены, колонны, другие паспорта; приоритет длинного фасада ×2). Перемещённые вручную (rPlaceX/Y ≠ позиции) не двигаются. Встроенные помещения 5xxx с номером «Квартира» — паспорт «АП» (iKind, 3 строки: номер, площадь, h=…). Размеры wCol1 7,5 / wCol2 9,5 / hRow2 4,4, шрифт 2,8, разделитель «,». GDL: имена переменных без учёта регистра (_h и _H — одна переменная!).
- ТЭП как в томе АР на рабочем листе «ТЭП» + таблица проверки справа (по каждой строке и секции: какие зоны, шт., м²) + Excel (листы «ТЭП», «Проверка ТЭП», «Квартиры»).
- Этажность = надземные этажи с 1-го до последнего с квартирами; количество этажей = этажность + подземные (отметка < −0,5 м, индекс < 0 или «подвал/подполье/подзем» в названии).
- Категории ТЭП (файл данных `Документы\ТЭП - <проект>.txt`, `# Версия: 4`, kConfigVersion = 4, MigrateConfigText v1→v2→v3→v4): п.5 подвал = 3; тех. = 3, −3030, −3070; подвальное и ЛК = 3030, 3070; п.6 встроенные = 5; п.11 кладовые = 4; п.12–13 нежилые = 6; п.14 общедомовые = 2 (надземные); не входят 8, 9. П.16 — студии, 1- и 2-комнатные отдельно с кухней и с кухней-столовой (строки всегда). Жители = приведённая / 30.
- При смене кодов по умолчанию — повышать kConfigVersion и дописывать миграцию + тест в tests/test_tep.cpp.

## Проверка зон на плане (графическая замена, с 06.11.2026)

- При каждом расчёте ведомости (`MarkZones` в Otdelka.cpp, отдельный шаг отмены) зонам расчёта и зонам других объектов на выбранных этажах пишутся свойства группы «ПСО и отделка»: «Отделка - подкатегория» (подкатегория / «Не входит»), «Отделка - проверка» (Верно / Замечания / Ошибка: нет отделки / Ошибка: нет подкатегории / Не входит / Другой объект зоны), «Отделка - замечание» (текст как в таблице проверки). Логика — `otd::CheckZone` (FinishTable.cpp, тест в test_otd.cpp).
- Свойства доступны по классификации: в availability добавляются классификации записываемых зон; зоны без классификации — не записываются (в отчёте).
- Надстройка сама создаёт группу правил графической замены «ПСО и отделка» (`OverrideRules`, критерий `CriterionXml`: тип «Зона» + свойство = значение, формат из экспорта AC27) и комбинации «Отделка - проверка зон» и «Отделка - подкатегории». Цвет — RGB фона покрывающей штриховки зоны (как в графзамене ZoneSum — только фон). Существующие правила не меняются; удалённые создаются заново и дописываются в комбинации.

## ZoneSum (паспорта) и будущая «Ведомость помещений»

- ZoneSum.apx — доработанный пример Graphisoft (Alexey Krikunov / Svetlana Kravchenko). Ищет объект зоны по имени «HimeraZone», объекты паспортов HimeraPassport/Section/House/FinishTable (сейчас ZoneSumPassport25, ZoneSumSection25 (typePassport=2), ZoneSumHouse25 (=3) — вызывают макрос ZoneSumPassport25).
- Читает из зоны: asAddOn_SubArea (тип пола), asAddOn_SubRegul (тип помещения), asAddOn_SubFinish (коэфф.), asAddOn_CalcArea, asAddOn_FloorArea, asAddOn_FillArea, asAddOn_stApartmentCode / stStaircaseCode / stHouseCode / stPositionCode, stRoomCode; пишет в паспорт ac_valueZoneAreas_number, ac_stZoneIds_name, ac_st*Code.
- План: своё приложение «Ведомость помещений» в этом же репозитории/надстройке (экспликация помещений по секциям и этажам по зонам HimeraZone_АСП, площади с коэффициентами, по образцу листа тома АР), при желании — замена ZoneSum с теми же параметрами asAddOn_*.

## Работа с пользователем

- Она проверяет на реальной модели (секция 2, подвал: коридор 21,2 м², электрощитовая 25,1 м²) и присылает скриншоты/эскизы с длинами. Отвечать конкретно: что было, почему, что изменено, ожидаемые цифры.
- После каждой правки: тесты → push → дождаться CI → сказать про артефакт, нужен ли перезапуск Archicad, заменится ли файл правил.
- Компьютер пользователя может быть связан через приложение Claude (mcp__remote-devices__*) — тогда можно самой класть .apx/.gsm в её папки. Подключены Документы и Загрузки (C:\Users\Лёля\…). device_commit_files иногда пишет старую версию — после записи сверять размер через device_list_dir.
